# Как вносить изменения

Устройство кода описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), мост для агентов
в [docs/MCP-BRIDGE.md](docs/MCP-BRIDGE.md). Здесь только порядок работы.

## Сборка и проверки

Нужна Windows 10 или 11. SDK, Visual Studio и NuGet не нужны: собирает `csc.exe`
из .NET Framework 4.x, который входит в систему.

```bash
build.cmd check
```

Команда собирает `bin\SafePaste.exe`, прогоняет тесты (`build.cmd test`) и проверки интерфейса
(`build.cmd uitest`). Перед отправкой изменений обе части должны пройти без ошибок. Снимки окон
после `uitest` лежат в `bin\ui-preview`: посмотрите их глазами, если меняли интерфейс.

Если запущен `bin\SafePaste.exe`, закройте его из меню значка перед `build.cmd`: файл занят.
Антивирус иногда не даёт запустить только что собранный exe, повтор через минуту обычно проходит.

## Правила кода

- **C# 5.** Нет интерполяции строк, `nameof`, `?.`, `out var`, инициализаторов автосвойств,
  кортежей и локальных функций. Лямбды, LINQ и `var` можно.
- **Без внешних пакетов.** Ссылки только на сборки из состава .NET Framework и WinMD из Windows.
- **`.cmd` и `.ps1` только в ASCII.** `cmd.exe` и Windows PowerShell 5.1 ломают разбор UTF-8
  с кириллицей.
- **Правила детекции меняются вместе с тестами.** Новое правило в `src/SafePaste/Detecting`
  получает проверки на то, что оно находит, и на то, что оно не трогает. Ложные срабатывания
  добавляйте в `tests/corpus` или в тесты рядом.
- **Только вымышленные данные.** В тестах, корпусе, снимках и описаниях задач используйте
  `example.com`, `example.test`, адреса из `10.0.0.0/8` и `192.0.2.0/24`, поддельные токены
  с `Fake` в теле. Настоящие пароли, ключи, адреса и ФИО не попадают в репозиторий никогда.
- **Тексты простым языком.** В интерфейсе и документации нет длинных тире, точек-разделителей
  `·` и двойных пробелов, вместо тире ставьте двоеточие или запятую. `build.cmd uitest`
  проверяет это в строках интерфейса.
- Комментарии и документация на русском, имена в коде на английском.

## Ветки и коммиты

- `main` всегда собирается и проходит `build.cmd check`.
- Работа идёт в отдельных ветках, в `main` попадает через pull request.
- Сообщение коммита: первая строка коротко о том, что изменилось для пользователя
  или для кода, дальше подробности, если нужны.
- Заметное для пользователя изменение записывается в [CHANGELOG.md](CHANGELOG.md),
  раздел «Не выпущено».

## Версии

Номер версии лежит в `AppInfo.Version` (`src/SafePaste/TrayApplication.cs`). Выпуск делается
тегом `vX.Y` на `main`: сборка в GitHub Actions соберёт exe, проверит его и создаст черновик
выпуска. Порядок описан в [docs/PUBLIC-LAUNCH.md](docs/PUBLIC-LAUNCH.md).
