# План публичного выпуска

Репозиторий закрыт, пока SafePaste дорабатывается. Здесь собрано, что нужно решить и сделать
перед тем, как открыть его и выложить первый выпуск. Пункты отмечаются в задаче
«Подготовка к публичному выпуску» на GitHub.

## 1. Решения владельца

- [ ] **Лицензия.** Пока файла `LICENSE` нет, все права у автора, и это правильно для закрытого
  репозитория. Варианты для открытия:
  - MIT: проще всего, разрешает любое использование, в том числе в закрытых продуктах;
  - GPL-3.0: производные версии тоже должны оставаться открытыми;
  - Apache-2.0: как MIT, плюс явная защита от патентных претензий.
  Для небольшой утилиты обычно берут MIT. Файл кладётся в корень как `LICENSE`.
- [ ] **Название.** Проверить, что `SafePaste` не занято похожим продуктом для Windows
  или расширением браузера, и что имя свободно в winget и Scoop.
- [ ] **Номер первого выпуска.** Сейчас в коде `0.4`. Предлагаю `1.0` для публичного выпуска,
  если всё из раздела 2 закрыто, иначе `0.5` с пометкой «предварительная версия».
- [ ] **Язык.** Интерфейс и документация на русском. Решить, нужен ли `README.en.md`
  с кратким описанием на английском для GitHub.

## 2. Доработки до выпуска

### Мост для агентов

Ревью 26 и 28 сентября 2026 нашло места, где агент может выйти за ограничения. Перед выпуском
перепроверить каждый пункт на текущем коде и закрыть подтверждённые:

- [ ] массив путей в аргументе команды обходит проверку разрешённых папок;
- [ ] `pattern` и `glob` в `sp_list` и `sp_find` проходят по junction за пределы папки;
- [ ] «На эту сессию» в окне подтверждения снимает вопрос для любых следующих операций того же вида;
- [ ] метка в имени для `Resolve-DnsName` и `nslookup` с чужим DNS-сервером проходит
  в ограниченном профиле;
- [ ] номера меток переиспользуются после удаления: старая метка указывает на новое значение;
- [ ] ошибки PowerShell не доходят до агента (`Error | Warning` в объединении потоков);
- [ ] «Остановить команду» не завершает дочерние процессы (нужен Job Object);
- [ ] разъём `--mcp` не переподключается после перезапуска SafePaste;
- [ ] безопасные значения по умолчанию для новой установки: пустой `Roots` сейчас открывает все
  файлы пользователя, `AllowFull` включён.

### Надёжность и скорость

- [ ] большой вывод команд (2 МБ) обезличивается порциями, без отказа по таймауту регулярки;
- [ ] вывод задачи не обезличивается заново целиком при каждом `sp_next`.

### Документация

- [ ] в [MCP-BRIDGE.md](MCP-BRIDGE.md) примеры запретов перечисляют MCP-серверы с машины автора
  (`local-qwen`, `unityMCP`, `blender`): заменить на общий пример;
- [ ] [MCP-BRIDGE-STAGE1.md](MCP-BRIDGE-STAGE1.md) описывает первый этап моста: перенести
  в `docs/history/` или убрать;
- [ ] решить судьбу `legacy/powershell`: оставить как архив или удалить из выпуска;
- [ ] в README добавить GIF с быстрой вставкой (10 секунд) и раздел «Ограничения» в начале.

## 3. Подпись и выпуск

Неподписанный exe, который читает буфер обмена, ловит горячие клавиши и посылает нажатия,
антивирусы и SmartScreen встречают предупреждением. Это главный риск для первых пользователей.

- [ ] **Сертификат для подписи кода.** Варианты: Azure Trusted Signing, обычный сертификат
  OV от удостоверяющего центра, SignPath Foundation (бесплатно для открытых проектов, нужна
  открытая лицензия). Подписывает [tools/Sign.ps1](../tools/Sign.ps1) по отпечатку сертификата.
- [ ] **Проверка антивирусами.** Отправить подписанный exe в Microsoft (Defender) и Kaspersky
  как ложное срабатывание до объявления выпуска.
- [ ] **Пробный выпуск.** Тег `v0.4-rc1` на `main`: workflow «Выпуск» соберёт exe, прогонит
  тесты и создаст черновик выпуска с архивом и SHA256. Скачать архив, проверить на чистой
  Windows 10 и Windows 11.
- [ ] **Первый выпуск.** Тег `vX.Y`, проверить черновик, опубликовать.
- [ ] Позже: манифесты для winget и Scoop.

## 4. Открытие репозитория

Вся история коммитов станет публичной. До переключения:

- [ ] прогнать поиск секретов по всей истории (`gitleaks detect` или аналог) и убедиться,
  что в репозиторий не попали настоящие адреса, пароли и ФИО. Поддельные токены из `tests/`
  исключены из проверки GitHub в `.github/secret_scanning.yml`;
- [ ] проверить снимки в `docs/images`: только вымышленные данные;
- [ ] переключить видимость:
  `gh repo edit --visibility public --accept-visibility-change-consequences`.

Сразу после:

- [ ] включить Private vulnerability reporting (Settings → Security), на него ссылается
  [SECURITY.md](../SECURITY.md);
- [ ] включить secret scanning и push protection;
- [ ] правило для `main`: изменения только через pull request с прошедшей сборкой
  (на бесплатном тарифе для закрытого репозитория правила веток недоступны);
- [ ] картинка для превью ссылки (Settings → Social preview, 1280×640);
- [ ] закрепить задачу с планом развития, включить Discussions, если нужны вопросы
  от пользователей.
