# Как устроен SafePaste

Документация для тех, кто правит код. Пользовательская часть лежит в
[QUICKSTART.md](../QUICKSTART.md) и [README.md](../README.md).

## Ограничения сборки

Собирает встроенный в Windows `csc.exe` из .NET Framework 4.x, поэтому:

- **язык C# 5**: нельзя интерполяцию строк (`$"..."`), `nameof`, `?.`, `out var`,
  инициализаторы автосвойств, кортежи, локальные функции. Лямбды, LINQ и `var` можно;
- **`.cmd` только в ASCII**: `cmd.exe` ломает разбор строк на UTF-8 с кириллицей;
- внешних пакетов нет, ссылки только на сборки из состава Framework
  (`System.Windows.Forms`, `System.Drawing`, `System.Security`, `System.Web.Extensions`).

```bash
build.cmd        # единый bin\SafePaste.exe, мост внутри
build.cmd mcp    # то же самое, для совместимости
build.cmd test   # bin\SafePaste.Tests.exe и прогон
build.cmd uitest # проверки интерфейса и снимки окон в bin\ui-preview
build.cmd check  # exe, тесты и UI-проверки
```

## Поток данных

```
буфер обмена ──> Detector.Scan ──> OverlapResolver.Resolve ──> ReviewForm (или сразу)
                      │                                              │
                 SafePasteDatabase                                   ▼
             (заученное, allowlist,                          Replacer.Apply
              закреплённые номера)                                   │
                                                                     ▼
                                         ClipboardService ──> Native.SendCtrlV ──> очистка
```

Решение о вставке принимает `TrayApplication.PasteSanitized`: он по очереди проверяет окно,
уровень целостности, отпущены ли клавиши и удалось ли вернуть фокус. Любая неудача здесь
не ошибка: обезличенный текст остаётся в буфере, пользователь вставляет его сам.

## Ключевые понятия

**Confidence** показывает, насколько детектор уверен. В обычном режиме:

- `High` скрывается и в быстрой вставке (`Ctrl+Shift+V`);
- `Medium` скрывается только в окне проверки (там оно включено по умолчанию);
- `Low` находка видна, но выключена: догадки вроде `DC01`, маски подсети и пути к файлам
  (`PATH` найден уверенно, но целиком его скрывает только строгий режим, об этом говорит
  `TypeNames.DescribeFinding`);
- `Learned` значение из базы, `Manual` отмечено в окне проверки; оба приравнены к `High`.

**ControlMode** ложится поверх уверенности и решает, что скрывается по умолчанию
(`ControlModes.HiddenInReview` для окна проверки и `HiddenInQuick` для быстрой вставки):

- `Strict` скрывает всё найденное, включая `Low`;
- `Balanced` ведёт себя как описано выше, это поведение по умолчанию;
- `Light` скрывает только `Locked` и значения из правил пользователя (`Learned`, `Manual`).
- `Bridge` скрывает также слабые догадки об именах, но оставляет маски, служебные адреса,
  встроенные SID и путь целиком; части пути скрываются. Это внутренний режим, в интерфейсе
  выбрать его нельзя.

`Locked` скрывается в любом режиме, allowlist действует в любом режиме. Сканеры режима
не знают: `Detector.Scan(text, database, mode, quick)` сначала запоминает мнение детектора
в `Detection.DefaultEnabled`, затем для быстрой вставки отбрасывает лишнее ещё до разбора
пересечений (так надёжная находка не пропадёт из-за выброшенной соседки), а для окна проверки
ставит галочки по режиму. Пересечения разбираются уже по этим галочкам, поэтому набор находок
зависит от режима там, где одна находка накрывает другие: в строгом режиме путь
`\\srv\share\dir\file.txt` включён и побеждает узел и папку внутри себя (`[PATH_1]`),
в обычном он выключен и уступает им (`\\[HOST_1]\[SHARE_1]\dir\file.txt`). По той же причине
переключатель режима в окне проверки проверяет текст заново, а не только меняет галочки.
Старый вызов `Scan(text, database, quick)` равен обычному режиму.

**Locked** значит обязательный секрет: галочкой его не снять, allowlist и быстрый режим его
не отключают, в окне значение показано точками, а видно оно в подсказке при наведении.
Снять секрет можно только явно, правым кликом: «Не скрывать в этот раз» кладёт в `choices` решение
`false`, и `ApplyChoices` после каждой проверки делает такую находку обычной выключенной (до смены
режима); «Распознано ошибочно» пишет значение в `SafePasteDatabase.NotSecrets`, и `Detector.Scan`
(а для картинки `ImageScanner.Detect`) больше не выдаёт его секретом. Сравнение с учётом регистра.
Список отдельный от allowlist: исключение для имени узла `test` не должно открыть `password=test`.

**Фраза вместо значения.** Общее правило `ключ: значение` берёт первое слово после двоеточия,
поэтому раньше «Пароль: не менее 8 символов» прятало «не». Теперь `ContextSecrets.IsProseValue`
отбрасывает значение без кавычек сразу после `:` (не после `=`: так пишут конфигурацию), если
оно короче трёх символов, служебное слово из `ProseWords` или русское слово, за которым идёт ещё
русское слово. Латиница в русской фразе («Пароль: qwerty для входа») остаётся паролем, слова
с цифрами и знаками не проверяются. `IsReference` узнаёт заглушки: одни тире, точки и вопросы,
слово в скобках `(empty)`, `[hidden]`, `TBD`, «нет», сочетания клавиш `Ctrl+...`.

**Priority** решает, кто побеждает при пересечении диапазонов. Шкала:

| Диапазон | Кто |
| --- | --- |
| 96–100 | секреты, токены, приватные ключи, ключи AWS |
| 85 | путь целиком (выше всего, что бывает внутри пути, но ниже секретов) |
| 71–86 | структурные идентификаторы: DN, почта, URL, Azure, отпечатки, MAC, UNC |
| 70 | IP, IPv6, SID, GUID |
| 73 | значения из базы (выше IP, чтобы задать свой тип; находки внутри них уступают им, см. ниже) |
| 69 | ФИО |
| 59–68 | контекстные догадки: host=, user=, имя пользователя в профиле, серийники, телефоны, имена без контекста; 66 имена по соседнему слову (`ContextNames`) |
| 95 | ручная отметка в окне проверки |

`OverlapResolver` сортирует по (включено, приоритет, длина, позиция, тип) и жадно набирает
непересекающийся набор. Выключенные находки не вытесняют включённые.

**Правила пользователя важнее того, что внутри них.** До сортировки `OverlapResolver` убирает
автоматические находки, которые целиком лежат внутри включённого значения из правил
(`Learned` или `Manual`). Без этого путь `\\domain\folder\it\tratata`, заученный целиком,
проигрывал узлу `domain` (приоритет 74 против 73) и скрывался кусками, а тип `HOST`
у заученного имени сменялся на `FQDN`. Исключения два: секреты (`Locked`) правило не забирает,
потому что правило можно выключить, а секрет нельзя; короткое правило внутри длинной находки
(имя внутри ссылки) ничего не забирает, и побеждает ссылка целиком.

**Границы заученных значений.** Заученное не находится внутри более длинного слова: `SRV-DB01`
внутри `SRV-DB01-old`. Граница проверяется только с той стороны, где значение начинается
или кончается буквой, цифрой, `_` или `-`. Разделитель на краю (`\`, `/`, точка) сам служит
границей, поэтому путь, выделенный вместе с последним `\`, находится и перед следующей папкой.
Заученное и запомненное ищет `ValueMatcher` за один проход: раньше это была одна регулярка
из всех значений, и уже 300 значений добавляли больше двух секунд на лог в 350 КБ, а 3000
не укладывались в таймаут и отменяли вставку. Автомат даёт те же совпадения (тест сравнивает
его с регуляркой на случайных строках), а 50 000 значений добавляют десятые доли секунды.
Одиночный шаблон `Detector.BoundedPattern` остался для `FindOccurrences`.

**Дубли.** `Detector.ScanContext` держит по одному кандидату на пару «диапазон + тип»
и оставляет более надёжного. Без этого порядок сканеров решал бы, победит ли значение
из базы или слабая догадка на том же месте.

**Нумерация.** `Replacer.NextNumber` выдаёт наименьший свободный номер для типа и пропускает
закреплённые в базе. Закреплённое значение всегда получает свой номер, поэтому `[IP_7]`
означает один и тот же адрес во всех вставках.

**ФИО.** `PersonNames` не берёт «любые два слова с заглавной буквы»: так начинается каждое
предложение и каждый заголовок. Сначала текст режется на цепочки слов с заглавной буквы
и инициалов, стоящих рядом через пробел. Слово после `\`, `/`, `@`, цифры или точки в цепочку
не входит: это адрес, путь или код. Затем в цепочке ищется опора:

- отчество (`-ович`, `-евна` и падежи) рядом с именем: «Иванов Иван Иванович», «Иван Иванович»;
- инициалы: «Иванов И.И.», «И. И. Иванов». При одном инициале нужна фамилия с привычным окончанием;
- имя из словаря `Lexicons.FirstNames` (с падежами: «Марии», «Сергеем») рядом со словом
  с окончанием фамилии (`-ов`, `-ина`, `-ский`, `-енко` и другие): «Иван Петров», «Марии Ивановой».

Пара из имени и незнакомого слова («Сергей Шойгу») остаётся догадкой `Low`. Обращения, должности,
глаголы прошедшего времени и частые слова на `-ина` и `-ов` («Машина», «Логин») перечислены
в `Lexicons.NameStopWords` и в имя не входят. Заглавными буквами пишут и сокращения (ООО, ИНН),
поэтому слову в верхнем регистре нужен признак имени, фамилии или отчества. Правила в `Rules.cs`
добавляют случаи с подписью рядом: «ФИО:», «Исполнитель:», `displayName`, «г-н», «сотрудник Иванов».

**Пути.** `FilePaths` находит путь целиком и делает его `Low`: целиком путь скрывает только строгий
режим. В обычном режиме скрываются части, которые говорят о людях и сети: узел и сетевая папка
(правило UNC в `Rules.cs`) и имя пользователя в профиле (`C:\Users\ivanov`, `/home/ivanov`,
тип `USER`). Папка с пробелами допустима в середине пути, а последняя часть с пробелами берётся,
только если кончается расширением («мой отчёт.docx»): иначе путь без кавычек съедал бы продолжение
фразы. Пути в кавычках берутся целиком. Относительные пути без корня берутся осторожно: с обратной
косой чертой не меньше трёх частей, с прямой ещё и расширение в конце, чтобы `and/or`, `TCP/IP`
и `application/json` путями не считались.

**Имена по соседнему слову.** `ContextNames` ищет имена, которые выдаёт только слово рядом: само имя
(«Orion», «Альтаир») ничем не отличается от обычного слова. Решение складывается из весов:

- подсказка перед словом: существительное из `ContextLexicons.Nouns` в любом падеже 2,5, глагол
  доступа или «RDP на» 2,0; явный контекст 4,5: ключ с `:` или `=` (`"cluster": "orion"`,
  `db_name: x`), аргумент команды (`ping`, `Test-NetConnection`, `Get-ADUser`), параметр
  (`-ComputerName`, `-Identity`, `mstsc /v:`), IP в скобках после слова, строка hosts, правовая
  форма (ООО «...», `Contoso Ltd`), название в кавычках после «компания», «проект»;
- вид слова: буквы с цифрами +2, подчёркивание +1,5, часть имени узла (`-pc`, `-srv`, `-prod`) +1,5,
  латиница в русской строке +1,5, заглавная буква не в начале фразы +1 (только в русском тексте:
  в английском заглавными пишут каждое слово заголовка), заглавные буквы +1, кавычки +2,
  CamelCase без цифр −1 (так пишут продукты).

От 3 находка `Medium`, от 4,5 при явном контексте или виде идентификатора `High`. После глагола
слово без цифр только `Low`. Не берутся строчные русские слова, короткие русские сокращения
(«СУБД»), продукты, протоколы и общие слова из `ContextLexicons.Known` и `Generic`, числа
с единицами (`64bit`), части адресов, путей и кода (точка, `\`, `/`, `@` рядом). Типы
существующие: `HOST`, `SHARE`, `USER`, остальное `TEXT`. Причина лежит в `Detection.Reason`
и показывается в подсказке. Приоритет 66: выше слабых догадок на том же месте, ниже ФИО и FQDN.

**Повторы.** В конце `Detector.Scan` вызывается `Repeats.Spread`: каждое включённое значение
ищется по всему тексту (`ValueMatcher`), и открытые вхождения получают ту же метку. Иначе подсказка
решала бы, где значение спрятано, а открытый повтор рядом выдавал бы метку. Производные значения:
короткое имя из FQDN и ссылки, учётная запись из `DOMAIN\user`, фамилия из ФИО во всех падежах
(`PersonNames.SurnameForms`, только вхождения с заглавной буквы). Типы, которые детектор и так
находит по виду (IP, FQDN, URL, почта), сами не повторяются. Телефон повторяется: короткий номер
узнаётся только после «тел.», а ниже он может стоять без подсказки. Секреты повторяются от 4 символов,
остальное от 3, числа от 6; обычные слова и исключения не повторяются. Вхождение внутри включённой
находки (имя внутри своего FQDN) пропускается, остальное ещё раз проходит `OverlapResolver`.
Поэтому частично скрытое значение (одно место скрыто, другое нет) детектор больше не выдаёт.

## Как добавить детектор

1. Простой случай: строка в `Rules.All` с шаблоном, типом, `Confidence`, приоритетом,
   именем группы (`value`) и `locked`. Несколько групп с разными типами задаются через
   `GroupTarget` (см. учётную запись и пароль внутри URL).
2. Если нужна логика сверх регулярки (разбор значения, словари, классификация), пишется
   отдельный сканер в `Detector.cs` и вызывается из `Scan`. Большой сканер можно вынести
   в свой файл, как `PersonNames` и `FilePaths`: он возвращает список находок, а `Scan`
   передаёт их в `ScanFound`.
3. **Обязательно** добавить в `tests/Tests.cs` и то, что должно скрываться, и то, что должно
   остаться: раздел `FalsePositiveTests` так же важен, как `SecretTests`.
4. Прогнать `build.cmd test`.

Полезные привычки в шаблонах: якоря `(?<!...)`/`(?!...)` вместо `\b` там, где важны точки
и дефисы; `[ \t]` вместо `\s`, чтобы не перескочить на следующую строку; `(?-i:...)` для
регистрозависимых кусков (MoRef, токены, `DOMAIN\`). Таймаут регулярки 750 мс, при превышении
бросается `DetectionTimeoutException` и вставка отменяется целиком.

## База

`%LOCALAPPDATA%\SafePaste\database.dat` хранит JSON под DPAPI (`CurrentUser`), формат
совместим с первой версией на PowerShell:

```json
{ "Sensitive": [ { "Value": "SRV01", "Type": "HOST" } ],
  "Allow": [ "example.com" ],
  "Reservations": [ { "Value": "10.44.7.219", "Type": "IP", "Index": 7 } ],
  "NotSecrets": [ "Release2024" ] }
```

`NotSecrets` появился позже: старый файл без него читается как пустой список.

Запись атомарная (временный файл и `File.Replace`). Правила согласованности: allowlist
вытесняет заученное значение и его закрепление, заучивание делает наоборот. Если файл
не читается, `SafePasteDatabase.Load` бросает `DatabaseException`, и вставка отменяется,
иначе заученные значения молча перестали бы скрываться.

`%LOCALAPPDATA%\SafePaste\labels.dat` хранит соответствие обычных меток значениям под DPAPI.
Мост и вставка из буфера используют общий файл; запись защищена именованным мьютексом и
атомарной заменой. Секреты живут только в памяти моста и в `labels.dat` не попадают.
Если файл меток повреждён, мост отказывает в ответе, а вставка отменяется с советом очистить
запомненные метки (`LabelStore.Clear` заменяет испорченный файл пустым).

**Запоминание меток** (`LabelMemory`) работает поверх того же файла:

- `Preview` даёт номера для показа и ничего не пишет; `Apply` вызывается, только когда текст уходит
  из окна (вставка, копирование результата, быстрая вставка), и при `SaveLabels` записывает метки
  всех скрытых значений. Без `SaveLabels` номера берутся из уже запомненного, файл не меняется.
- Не записываются секреты, находки с `Detection.Transient` («Отметить без сохранения») и выключенные
  находки: `LabelStore.Apply` пропускает `Transient`, а в `Replacer` попадают только включённые.
- `Load` кладёт запомненное в `SafePasteDatabase.Remembered`: это отдельный список, в `database.dat`
  он не пишется. Детектор ищет его вместе с заученным (`Confidence.Learned`, `Source` =
  `Detection.RememberedSource`); правило пользователя с тем же значением важнее. Срок берётся
  по режиму (`ActiveDays`): строгий 30 дней с последнего использования, обычный 14, лёгкий 0;
  `RememberDays` задаёт срок вручную, `HideRemembered` выключает поиск. Короткие значения,
  короткие числа, слова из одних строчных букв и стоп-слова (`LabelMemory.IsDistinctive`)
  без подсказок не ищутся: иначе `hostname: test` прятал бы слово test во всех текстах.
- «Никогда не скрывать» забывает метку значения (`Forget`), кнопка в «Правилах и исключениях»
  забывает все (`Clear`), закреплённые номера и правила при этом остаются. Сам `labels.dat` держит
  метку 30 дней с последнего использования: мосту она нужна для продолжения переписки.

`%LOCALAPPDATA%\SafePaste\bridge.json` хранит настройки моста отдельно от `settings.json`.
`BridgeHost.CurrentSettings` перечитывает файл, когда меняются время записи или размер, поэтому
правка из окна или из установщика действует на следующий вызов. `settings.json` все окна меняют
через `SafePasteSettings.Update` (прочитать свежий файл, поменять своё, записать), поэтому окно
проверки больше не затирает выключатели, переключённые в трее, пока оно открыто.

## Мост внутри трея

```
агент ── stdio ──> SafePaste.exe --mcp ── \\.\pipe\SafePaste-Bridge-<SID>-<хеш папки данных> ──> трей
                   (McpRelay)                                                      BridgeHost
                                                                                     │ сессия на агента
                                                                                     ▼
                                                                          McpServer ──> ExternalWorker
                                                                                        (--worker)
```

- `TrayApplication` запускает `BridgeHost` до стартовых предупреждений: агент мог сам запустить
  SafePaste и ждёт канал. Окна подтверждения показывает поток интерфейса через `PromptApproval`.
- Канал создаётся через `CreateNamedPipe`: DACL только для SID пользователя,
  `PIPE_REJECT_REMOTE_CLIENTS`, первый экземпляр с `FILE_FLAG_FIRST_PIPE_INSTANCE`, чтобы чужой
  процесс не мог заранее занять имя. Разъём со своей стороны сверяет владельца процесса-сервера
  (`GetNamedPipeServerProcessId`): имена каналов общие для всех пользователей машины.
- Первая строка от разъёма `{"safepaste":"hello","cwd":...}`: рабочая папка агента становится
  текущей папкой сессии, если она внутри разрешённых папок.
- Метки и секреты общие для всех сессий (`LabelStore` один на запуск моста), у каждой сессии свои
  воркеры, текущая папка и разрешения «на эту сессию». Выключение моста начинает с чистой памятью.
- Воркеры запускаются под общей блокировкой: дочерний процесс наследует все наследуемые
  дескрипторы, и концы каналов одной сессии не должны попасть в воркер другой.
- Если SafePaste не запущен, разъём запускает его через `CreateProcess` с
  `CREATE_BREAKAWAY_FROM_JOB` и средой пользователя из `CreateEnvironmentBlock`: клиент агента
  может завершать задание (job) вместе с собой и урезать переменные среды, а трей и его воркеры
  должны жить дальше в обычной среде. `--bridge-host` поднимает тот же мост без трея для дымовой
  проверки (`tools/BridgeSmoke.ps1`).

## Интерфейс

### Стекло

В Windows 11 22H2 и новее `Native.EnableGlass` включает у окна системный фон Acrylic
(`DWMWA_SYSTEMBACKDROP_TYPE`) и растягивает рамку DWM на всё окно
(`DwmExtendFrameIntoClientArea` с полями `-1`). После этого DWM смешивает пиксели окна
с размытым фоном по их альфа-каналу. Отсюда главное правило: **все элементы свои**.

- Стандартные `TextBox`, `RichTextBox`, `ListView` рисуют через GDI, а GDI пишет альфу 0.
  На стекле такие элементы просвечивают насквозь, и текст на ярком фоне не читается.
- Свои элементы наследуют `GlassControl`: двойная буферизация, отрисовка GDI+ с настоящей
  альфой, прозрачный фон (`SupportsTransparentBackColor`). Родитель дорисовывает свой фон
  в буфер ребёнка, поэтому непрозрачных прямоугольников не остаётся.
- Слои задаются цветами с альфой в `Theme` (`WindowGlass`, `Well`, `Fill`...). Без стекла
  (Windows 10, удалённый рабочий стол, `Theme.ForceSolid` в проверках) те же слои ложатся
  на сплошной фон, код отрисовки один.
- Текст рисуется GDI+ со сглаживанием `AntiAliasGridFit`: ClearType на прозрачном фоне
  даёт цветную кайму.

Окна без системной рамки (`GlassForm`): пустой фон отвечает на `WM_NCHITTEST` как заголовок,
поэтому окно перетаскивается за любое свободное место; края меняют размер; двойной щелчок
разворачивает окно на рабочую область. Скругление углов и тень даёт DWM.

### Окно проверки

- Переключатель режима в шапке (`Ctrl+1`, `Ctrl+2`, `Ctrl+3`) вызывает `ReviewForm.ApplyMode`:
  текст проверяется заново (`Rescan`), галочки ставятся через `ControlModes.HiddenInReview`, режим
  сохраняется в `settings.json` и дальше действует на быструю вставку. Тот же выбор есть в меню
  значка (`TrayModeItem`).
- Исходный текст правится прямо в блоке (`TextView.ReadOnly = false`). `TextView` сам текст
  не меняет, а просит правку событием `EditRequested` в позициях показанного текста.
  `ReviewForm.OnPreviewEdit` переводит их в исходные через `TextMap.CaretToOriginal`
  и `RangeStartToOriginal`: вставка в конце строки не разрывает `\r\n`, Backspace удаляет
  табуляцию целиком. Переводы строк в набранном тексте такие же, как в исходном.
- `ApplyEdit` только сдвигает находки (`ShiftDetections`), а проверка заново идёт после паузы
  в наборе. Задетая правкой находка пропадает до проверки, кроме секрета: он растягивается
  на изменённое место и остаётся закрытым точками.
- `BuildResult` и кнопка вставки сначала вызывают `FlushScan`, поэтому результат никогда
  не строится по старым находкам. Если проверить текст не удалось, вставка отменяется.
- Решения переживают проверку заново: галочки по значению лежат в `choices`, отметки вручную
  (и секреты «только сейчас», которые в базу не пишутся) в `manualMarks` и сдвигаются вместе
  с текстом. Смена режима сбрасывает галочки, но не отметки. Новый текст целиком (`LoadText`,
  `Ctrl+A` и `Ctrl+V`) проверяется с чистого листа. `EditHistory` хранит правки для `Ctrl+Z`
  и `Ctrl+Y` и склеивает набор подряд.
- В поле правки `Ctrl+V` вставляет текст в место курсора (`TextView.ProcessCmdKey` забирает
  сочетание раньше окна). Если фокус в другом блоке, `Ctrl+V` по-прежнему заменяет весь текст.
- `TextView` показывает текст моноширинным шрифтом с переносом по словам: без горизонтальной
  прокрутки, а попадание мышью и подсветка считаются по столбцам. Рисуются только видимые
  строки, поэтому мегабайт текста не тормозит.
- `TextMap` переводит позиции между буфером и показанным текстом: `\r\n` показывается одним
  символом, табуляция раскрыта в пробелы, управляющие символы видны точкой.
- Подсветка (`TextMark`) строится из находок: заменится, останется, секрет, метка в результате.
  Подсказка при наведении собирается в `ReviewForm.DescribeSourceMark`.
- Синхронная прокрутка: `ReviewForm.BuildSegments` запоминает, где каждая замена стоит
  в исходнике и в результате, `SourceToResult` и `ResultToSource` переводят позицию верхней
  видимой строки из одного блока в другой.
- Панели результата и находок раскрываются кнопками `Spine`; окно при этом растёт вправо
  или вниз в пределах рабочей области, состояние сохраняется в `settings.json`.
- Контекстные меню (`GlassMenu`) собираются заново на каждый правый клик и удаляются после
  закрытия. Методы `BuildPreviewMenu`, `BuildResultMenu`, `BuildListMenu` проверяются тестами.
  Пункт добавляется, только если его можно применить к месту под мышью; пустое меню не
  показывается (`GlassMenu.Tidy`). Правка, поиск и замена всего текста в меню не повторяются.
  Для выделенного (`AddSelectionActions`): «Отметить» (`MarkTypes.Generic`, `HIDE_TEXT`, с правилом),
  вложенное меню «Пометить как» (`GlassMenu.AddSubmenu`) с типами из `MarkTypes.For`: сначала типы,
  чей строгий вид совпал с текстом, потом остальные по счётчику выбора (`MarkTypes` в `settings.json`),
  и «Отметить без сохранения» (`Detection.Transient`). Пароли, токены и ключи в правила не пишутся,
  у них нет «Закрепить номер» и «Скрывать всегда». У секрета (`AddGroupActions`) пункты
  «Не скрывать в этот раз» и «Распознано ошибочно» (`ReleaseSecret`), в заголовке меню само значение;
  выделение внутри пароля показывает те же пункты. Отметка паролем вручную снимает «Распознано ошибочно».
- Одинаковые кнопки одинаковы везде. Поворот значка при наведении задаёт `GlassButton.DefaultTurn`
  по самому значку (крестик и шестерёнка на 90°, стрелки на 180°), а не каждое окно. Шапки картинки
  и распознанного текста устроены одинаково: легенда, переключатель вида, стрелки «взять из буфера»
  (`BlockHeader.InsertTool`), поэтому второй щелчок по переключателю не попадает в стрелки. Внизу
  постоянные «Вставить» и «Копировать» стоят справа на своих местах, а кнопки, которые есть
  не всегда («Вставить все», «Вставить текстом»), добавляются левее.
- `BuildResult` показывает результат и ничего не пишет; `BuildPasteResult` вызывают вставка
  и копирование, он запоминает метки (`LabelMemory.Apply`). Если текст правили и не проверили,
  оба сначала проверяют его.
- Шестерёнка в шапке открывает `SettingsForm` с теми же `SettingsActions`, что и трей: окно одно
  на всё приложение (`TrayApplication.ShowSettings`). Открытое до окна проверки заблокировано её
  модальным циклом, поэтому по шестерёнке оно открывается заново, уже поверх окна проверки. Правила,
  метки и выключатели могут поменять другие окна, пока окно проверки открыто: при активации и при
  каждом переключении в окне настроек (`SettingsChanged`) `ReloadIfChanged` сравнивает время записи
  `database.dat`, `labels.dat` и `settings.json`, перечитывает изменившееся и проверяет текст заново,
  только если набор правил или запомненного правда изменился (мост часто пишет в `labels.dat` одни даты).
- Анимация (`Tween` в `Motion.cs`): кнопки, переключатели режима, раскрывающие полосы и строки
  настроек держат плавные значения, которые обновляет один общий таймер, и только пока что-то
  движется. Элемент в непоказанном окне и выключенные в Windows эффекты анимации
  (`SPI_GETCLIENTAREAANIMATION`) ставят значение сразу, поэтому снимки `uitest` не зависят от времени.
  Значки круглых кнопок рисуются контуром (`Theme.FillGlyph`), чтобы не дрожать при повороте.
- Горячая клавиша окна проверки открывает его и без текста в буфере; если буфер занят другой
  программой, причина видна в строке состояния (`ReviewForm.ShowNotice`).
- **Вкладки** (`ReviewTabs.cs`). Поля окна (`sourceText`, `detections`, `history`, `choices`,
  `manualMarks`, `scanPending`) принадлежат открытой вкладке: `SaveDocument` переносит их в запись
  `Document`, `LoadDocument` возвращает, поэтому весь прежний код проверки работает с одной вкладкой
  и не знает о других. Смена режима и правил помечает остальные вкладки `Stale`: они проверяются
  заново, когда их откроют. Новые вкладки приходят из `TrayApplication.OfferCopy`: пока окно открыто,
  `WM_CLIPBOARDUPDATE` предлагает окну текст из буфера. Свои записи SafePaste отличаются по номеру
  изменения буфера (`ClipboardService.IsOwnChange`, `GetClipboardSequenceNumber`), копии с форматами
  `ExcludeClipboardContentFromMonitorProcessing` и `CanIncludeInClipboardHistory` = 0 пропускаются.
  Вставка вкладки при других открытых идёт через `PasteRequested`: трей вставляет, окно остаётся.
  `BuildAllResult` склеивает вкладки через пустую строку и считает замены одним проходом, чтобы
  номера не разошлись между вкладками. `Visible` у элементов непоказанного окна всегда false,
  поэтому раскладка смотрит на число вкладок и флаг `pasteAllShown`, а не на `Visible`.
- **Расшифровка.** `Ctrl+Shift+C` (`TrayApplication.StartDecrypt`) ждёт, пока отпустят клавиши,
  нажимает `Ctrl+Insert` (Insert с флагом расширенной клавиши, иначе это «0» цифрового блока)
  и до 700 мс ждёт, пока изменится номер буфера. Вкладка расшифровки хранит `LabelDecoder.Decode`
  и показывает `DecodedText.Text` только для чтения: восстановленное подсвечено `MarkKind.Restored`,
  нерасшифрованное `MarkKind.Missing`. Результат, список, переключатель режима и вставка на этой
  вкладке скрыты, `Ctrl+Enter` копирует.
- Подсказка `GlassTip` одна на всё приложение: не забирает фокус и пропускает мышь сквозь себя.
- Сообщения показывает `Alerts` (`GlassDialog`). `MessageBox` остался только как запасной путь,
  если своё окно показать не удалось.

## Отладка без запуска exe

Антивирус может не давать запускать свежесобранный `SafePaste.exe`. Тогда собирается
библиотека и вызывается из Windows PowerShell (тот же рантайм .NET Framework):

```powershell
$dll = "$env:TEMP\sp.dll"
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /target:library /out:$dll `
  /r:System.dll /r:System.Core.dll /r:System.Drawing.dll /r:System.Windows.Forms.dll `
  /r:System.Security.dll /r:System.Web.Extensions.dll `
```

Формы внутренние, поэтому создаются через
`GetConstructors([Reflection.BindingFlags]'NonPublic,Instance')`. Все элементы интерфейса
рисуют себя сами, поэтому `DrawToBitmap` снимает окно целиком, в том числе текст. Снимок
отражает сплошной режим; как выглядит стекло, видно только на экране, потому что размытие
добавляет DWM при выводе.
